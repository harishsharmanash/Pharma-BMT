# TICKET H1 — Render smoke coverage for three more routes

## Why this matters (read before writing anything)

These pages have been restyled repeatedly, and the failure mode we keep hitting is **silent
subtraction**: a restyle drops a feature, and `tsc` + the existing suite stay green because the code
is still valid. Your tests exist to pin the things a future restyle is most likely to delete.

## The pattern to copy — READ IT FIRST

`--read src/test/detail-routes.render.test.tsx`. Copy its structure exactly:

1. `vi.mock("@tanstack/react-router", ...)` where **`createFileRoute` returns the options object**.
   That is how the real page component is reached without exporting internals from route files:
   `const Component = (SomeRoute as { options: { component: ComponentType } }).options.component`.
2. `vi.mock("@/integrations/supabase/client", ...)` with the chainable, thenable builder stub, and a
   `TABLE_ROWS` map keyed by table name. **Add whatever tables these three pages query** — read the
   hooks they use (`use-products.ts`, `use-staff.ts`, `use-leads.ts`, `use-orders.ts`) to find the
   table names. Fixtures must be shaped like real rows.
3. Mock `@/lib/auth-context`, `@/lib/use-permissions` (**`useMyPermissions` returns a `Set`
   directly, NOT `{data: Set}`** — getting this wrong throws `myPerms.has is not a function`),
   `@/lib/use-features`, `@/components/app-shell` (`Protected` passthrough) and
   `@/components/feature-gate` (`FeatureGate` passthrough).
4. Wrap renders in `QueryClientProvider` **and `TooltipProvider`** — these pages use Radix tooltips
   and throw "`Tooltip` must be used within `TooltipProvider`" without it.
5. Import the route modules **statically** (`import { Route as DashboardRoute } from "@/routes/dashboard"`).
   A dynamic `import(variablePath)` does not resolve through the `@/` alias.
6. React 19 has no global `JSX` namespace — type the component as `ComponentType` from `react`.

## What to assert on each page

Render it, wait for data, and assert the sections/values a restyle could silently drop. Prefer
`getAllByText(...).length` over `getByText` — several of these strings legitimately appear more than
