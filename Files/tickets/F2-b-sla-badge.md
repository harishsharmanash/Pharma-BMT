## Goal

Render a live SLA countdown badge on uncontacted leads, driven by the per-company thresholds from
migration `20260822120000_speed_to_lead.sql` (attached as --read — it is APPLIED or about to be;
code must compile against the columns regardless via the `as any` house convention where needed).

Semantics (owner/spec decisions — do not re-litigate):

- Arrival time is `created_at` (machine-generated by the intake worker, trustworthy). NOT
  `date_received` (date-only).
- Grade = lead `temp`. NULL/unknown temp falls back to the WARM threshold.
- A lead is "uncontacted" only when `first_contact_at IS NULL` **and** `stage = 'New'`. Legacy
  leads past 'New' with no timestamp are treated as contacted (no badge, excluded from stats).
- Won/Lost leads never show a badge.
- Badge states: **green** = under 75% of the SLA elapsed; **amber** = 75%–100%; **red** = breached.
- F15's future `lead_uncontacted` task kind will reuse these helpers — keep them pure and exported.

### 2. New pure module `src/lib/speed-to-lead.ts` + `src/lib/speed-to-lead.test.ts`

```ts
export type SlaConfig = { sla_hot_minutes: number; sla_warm_minutes: number; sla_cold_minutes: number };
export const DEFAULT_SLA: SlaConfig = { sla_hot_minutes: 15, sla_warm_minutes: 120, sla_cold_minutes: 1440 };
export type SlaState = "within" | "approaching" | "breached";

export function slaMinutesForTemp(temp: string | null | undefined, cfg: SlaConfig): number;
export function slaStateFor(
  lead: { first_contact_at?: string | null; stage: string; temp: string | null; created_at: string },
  cfg: SlaConfig,
  now: Date,
): { state: SlaState; deadline: Date; minutesLeft: number } | null;
export function slaBadgeLabel(minutesLeft: number): string; // "12m left" / "1h 5m left" / "8m over" / "2h 3m over"
```

- `slaStateFor` returns null for contacted/closed leads per the semantics above.
- `minutesLeft` is `deadline - now` in whole minutes, negative when breached.
- Label: under 60 minutes → "Nm left/over"; else "Xh Ym left/over". No seconds, no days.
