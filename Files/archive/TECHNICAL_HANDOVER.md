## Conventions & gotchas (important)
- **Hand-written types:** the row types (`Product`, `Party`, `Lead`, `Order`, etc.) are defined by hand in `src/lib/use-*.ts`, and query results are cast (`data as Party[]`). When you add a DB column, add it here as **optional** (`foo?: T | null`) so reads/writes compile before `types.ts` is regenerated.
- **New tables / unknown columns:** `.from("newtable")` / `.rpc("newfn")` won't type-check until `types.ts` regenerates. Cast: `(supabase.from("x") as any)…` or `(supabase.rpc as any)("fn")`. Used for `party_status_history`, soft-delete writes, and `generate_lead_followup_notifications`.
- **Prefer direct RLS over edge functions.** Example: Manage Users edit was broken by a stale deployed edge function; the fix updates `profiles` directly from the frontend (admins can update rows in their own company per RLS). Do the same for new admin-ish writes where RLS allows it.
- **Soft delete:** leads/parties/orders/products have `deleted_at`. List hooks filter it out client-side (`.filter(r => !r.deleted_at)`); delete mutations set `deleted_at` (cast to any); the Trash page restores (`deleted_at = null`) or purges (`.delete()`).
- **Order totals** are computed by DB triggers on `order_items` insert — don't compute them client-side; just insert the order + items via `useSaveOrder`.
- **RLS helpers** in the DB: `current_company_id()`, `current_role()`, `is_admin()`, `is_manager_or_admin()` (SECURITY DEFINER) gate most policies.
- **Sandbox can't run `tsc`/`npm install`** (times out). Verify by reading + grep + live test on preview.
- **Live-test technique:** get the JWT from `localStorage['sb-crzddmxogxhirzqkrgwb-auth-token']` in a signed-in tab and `fetch()` Supabase directly with `apikey` (publishable key from `.env`) + `Authorization: Bearer <jwt>`. Bypasses UI error-swallowing.

## File-import / OCR engine
- `src/lib/file-extract.ts` — `extractRecordsFromFile(file, onProgress)`: routes by type → SheetJS (xlsx/csv), mammoth (docx), DOM (html), pdf.js text layer (digital PDF), tesseract.js OCR (scanned PDF/images). Heavy libs are `import()`-ed lazily inside functions (SSR-safe). Returns `{ rows, rawText, kind, confidence, note }`. Exports `ACCEPTED_FILE_TYPES`.
- `src/lib/import-products.ts` — `parseProductsFromExtract(res)` → `ProductDraft[]`. Header-map for tables; pharma regex for OCR lines. **Rule:** strengths (mg/mcg/iu/%) → Composition; real packaging (NxM, ALU-ALU, blister, bottle/ml + dosage form) → Pack; brand separated from salt.
- `src/lib/import-orders.ts` — `parseOrderFromExtract(res)` → one `ImportedInvoice`. Structured → reuse `guessMapping`+`rowsToInvoices` (from `use-orders.ts`); OCR/text → per-line item parser. The order importer maps these to named-column rows and feeds the existing map→preview→create flow.
- UI: New Product / New Order are dropdowns (Upload file / Add manually). Product upload opens an editable review sheet before insert; imports return inserted ids for **Undo import**.
- **Weakness:** photos/scans of dense bills are best-effort (free OCR); the review step is the safety net. Higher accuracy = document-AI API or vision LLM (paid; mind the edge-function redeploy caveat).
